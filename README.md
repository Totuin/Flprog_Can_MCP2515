# Flprog_Can_MCP2515 — заготовка драйвера MCP2515

**Версия:** 1.0.1 (ревизия исходников)  
**Статус:** не реализован SPI-драйвер, НЕ готово к CAN-обмену на оборудовании.

## Назначение

Каталог содержит предварительные таблицы конфигурации регистров CNF1/CNF2/CNF3 для MCP2515 с кварцевыми резонаторами 8, 16 и 20 МГц и объявление класса `FLProgMCP2515CanBus`, наследующего `FLProgAbstractCanBus` из `Flprog_Can`.

**Ключевое ограничение:** исходная версия не содержала реализации SPI, функций `begin()`, приёма, отправки, фильтров или очередей. В 1.0.1 аппаратная реализация **не добавлялась**: расширение функций CAN-передачи без аппаратной проверки было бы ошибочным. Унаследованный метод `write()` возвращает `false`, `hasNewReadMessage()` возвращает `false`.

## Что добавлено в 1.0.1

1. Различимые константы `FLPROG_MCP_CAN_CLOCK_20MHZ = 0`, `...16MHZ = 1`, `...8MHZ = 2`. Эти коды соответствуют имеющемуся перечислению `FLPROG_MCP_CAN_CLOCK`.
2. Функция `flprogMcp2515GetBitTiming(clock, speed, result)` выбирает известную конфигурацию регистров, **не обращаясь к SPI**.
3. Функция возвращает `false` для неизвестных сочетаний кварца/скорости и запрещённых временных сегментов. При отказе структура `result` не меняется.
4. Добавлены комментарии в `.h`, исправлены метаданные и расширен `keywords.txt` (включены элементы перечислений и новый helper).
5. Тесты содержат расчёт частоты битов по регистрам, проверяют 37 исходных таблиц и линковку с реальной `Flprog_Can 1.0.1`.

## Пример выбора CAN-тайминга (не настройка устройства!)

```cpp
#include <flprog_Can_MCP2515.h>

void setup() {
  FLProgMCP2515BitTiming timing = {};
  if (flprogMcp2515GetBitTiming(FLPROG_MCP_CAN_CLOCK_16MHZ,
                                FLPROG_MCP_CAN_SPEED_500KBPS, timing)) {
    // timing.cnf1, timing.cnf2 и timing.cnf3 содержат настройки.
    // Никакой реальной записи в MCP2515 функция НЕ выполняет.
  }
}
void loop() {}
```

## Ограничения таблиц

- 8 МГц / **1000 кбит/с**: в исходной таблице PS2 равен 1 TQ, что не удовлетворяет требованию MCP2515 (не менее 2 TQ). Для этого сочетания helper возвращает `false`. Старые макросы сохранены для совместимости, но использовать их для прошивки регистров нельзя.
- 95 кбит/с: объявлены код скорости и перечисление, но нет ни одной комбинации CNF1/CNF2/CNF3. Helper возвращает `false`.
- 31,25 кбит/с: таблица присутствует только для 8 МГц; 83,3 кбит/с — только для 16 МГц.
- Остальные отсутствующие комбинации также возвращают `false`.
- Все существующие значения регистров (макросы `*_CFG1/2/3`) оставлены исходными, без неиспытанных «улучшений» параметров sample point.

## Для завершения реального драйвера

Необходимо спроектировать и испытать SPI-транспорт, инициализацию микросхемы, выбор частоты кварца, управление режимами normal/loopback/listen-only, запись/чтение кадра (включая extended ID и RTR), RX/TX-буферы, маски/фильтры, обработку прерываний, ошибки CAN (включая bus-off) и совместимость с `FLProgAbstractCanBus`.

**Важно:** сам MCP2515 — контроллер CAN, а для физических CANH/CANL требуется отдельный трансивер. Перед тестированием проверьте напряжения и корректную разводку SPI, CS, INT, питание и согласование CAN-шины.

**Документация:** [Microchip MCP2515 Family Data Sheet DS20001801K](https://www.microchip.com/content/dam/mchp/documents/APID/ProductDocuments/DataSheets/MCP2515-Family-Data-Sheet-DS20001801K.pdf), раздел 5.7, регистры CNF1–CNF3.

## Зависимости и проверка

- Для компиляции нужен пакет `Flprog_Can 1.0.1` и `Flprog_Utilites`.
- Тесты C++11 проверяют компиляцию и вычисления **на заглушках Arduino**.
- Проверка на реальном Arduino Core и модуле MCP2515 не проводилась; она необходима для полноценного будущего драйвера.
